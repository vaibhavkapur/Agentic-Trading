# Runbook and acceptance evidence

## Operate and reproduce

1. Use the README commands from the project root. Run the full dependency-backed tests before changing the adapter. The core-only suite explicitly skips the third-party checker.
2. For a custom experiment copy the versioned configuration and pass `python3 scripts/demo.py --config path/to/config.json --out path/to/new-directory`. Preserve the printed directory with the experiment. Identical settings and fixture yield identical decisions. Exact numerical byte comparisons in the reproduction script target the reference Python and platform recorded in provenance.
3. Inspect `runs.jsonl` for candidate budgets, episode returns, unsuccessful candidates, validation scores, selected candidates and the final completion event. `metrics.json` contains fold-level outcomes. Inspect `decisions.csv` for per-step fills and account balances. Use `summary.json` for aggregate estimates. An incomplete directory can contain partial evidence. Require `experiment_complete` before consuming an export.
4. On a nonzero exit, inspect the error code and message in the journal. Verify the fixture hash, configuration and window lengths. A write failure may prevent recording a failure event. Preserve the original run and retry in a fresh directory after correcting the input. The safe fallback is to stop the simulation. A separate cash-only baseline provides a reference.
5. To rebuild the bundled synthetic input, run `python3 scripts/generate_fixture.py` and verify its manifest digest against the retained experiment provenance. The generator replaces its own CSV and manifest. Changing the generator requires a new reference run.

The GitHub Actions workflow installs the adapter lock, runs the suite and retains the demo output. The supplied directory is a standalone project with no configured remote CI run. Local full-suite output is retained in [validation.txt](../reports/validation.txt).

## Acceptance evidence

- **Observation timing and action limits.** [Fault scenarios](../tests/scenarios/test_controls.py) alter future prices and delay publication, reject invalid actions before state mutation and exercise terminal reward farming.
- **Cash, inventory, costs and risk.** [Accounting tests](../tests/unit/test_accounting.py) reconcile every fill and overnight move, check half allocations on both sides and prove cumulative reward conservation. Scenario tests cover zero liquidity, adverse prices, participation limits, stress and fee sensitivity.
- **Comparable policies and uncertainty.** The [reference report](../reports/reference/report.md) compares all policies on identical held-out windows. [Integration tests](../tests/integration/test_experiment.py) match their timestamps, verify validation-based selection, replay serialized actions and compare repeated runs. [Raw decisions](../reports/reference/decisions.csv), [candidate records](../reports/reference/runs.jsonl) and [fold metrics](../reports/reference/metrics.json) accompany the report.
- **Training and deterministic reproduction.** The learning unit test checks that Q-learning can capture a known rising path under zero costs. Seed tests reproduce full episode scores. The [inference artifact](../reports/reference/paper-policy.json) embeds selection metadata and the [provenance file](../reports/reference/provenance.json) identifies the runtime, fixture, code and configuration.
- **Integration and failure handling.** The Gymnasium checker runs in the pinned environment. The CLI tests inject a fixture digest mismatch, insufficient history and an existing output directory. Failed runs retain their journals. An existing directory is never reused.
- **Local security and rights review.** The fixture is generated from original code, with no third-party market records or portfolio data. The core uses only Python’s standard library. The optional adapter uses the dependencies pinned in the project. The loader reads JSON and CSV as data. Artifacts contain observations, actions and metadata without executable model serialization. File hashes detect mismatched inputs but do not authenticate a publisher. Local filesystem permissions govern access.
- **Deployment review status.** This deliverable is a local research prototype. An exported action table confers no execution authority. No operator credentials, broker adapter or order transport are present. External data rights, ownership sign-off, independent risk/security review and any broker, legal or regulatory approvals for a future deployment remain with the project owner.
